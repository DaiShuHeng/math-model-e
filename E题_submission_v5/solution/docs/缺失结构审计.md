# 缺失结构审计：附件 2/3/4 的实际缺失模式

> 审计对象：`aligned_50.pkl`（train/valid/test）、`附件3-模态缺失特征样本/对齐版本`
> 30 条、`附件4-可解释专项视频样本与特征文件/对齐版本` 20 条。
> 全部结论来自对赛题提供文件的直接统计，未使用任何外部数据，也不读取任何标签之外的
> 专项测试信息。

## 1. 观测掩码的定义

按赛题"特征值全部为零的随机连续序列区间"的表述，本稿把一行特征是否可用定义为

```
observed(i) = not all_close(x[i, :], 0)
```

零行只是"该位置不可用"的**操作性约定**，它本身不证明缺失的物理成因。

## 2. 核心发现

### 2.1 音视频的可用范围被文本 token 跨度严格界定

令 `L` 为 `text_bert[1]`（attention mask）之和，即该样本的有效 token 数。统计：

| 数据集 | 音视频零行落在 token 跨度**之外**的比例 | 音视频观测掩码与 token 跨度**完全相等**的样本比例 |
|---|---:|---:|
| train (n=3395) | **100.00%** | 音频 95.96% / 视觉 93.50% |
| valid (n=728) | **100.00%** | 音频 95.87% / 视觉 93.31% |
| test (n=727) | **100.00%** | 音频 96.00% / 视觉 93.18% |
| 附件 3 (n=30) | **100.00%** | 与训练集同量级 |
| 附件 4 (n=20) | **100.00%** | 与训练集同量级 |

换言之：**不存在"音视频在整个序列上随机缺失"的样本**。音视频只在与文本 token 对齐的
位置上被观测；位置 `0` 与 `[L, 50)` 在几乎所有样本上恒为零。

### 2.2 语音与视觉的缺失完全同步

| 数据集 | `a_obs == v_obs` 的样本比例 |
|---|---:|
| 附件 3（30 条） | **100.00%** |
| 附件 3 逐条统计 | 30/30 条完全相同 |
| train | 97.54% |
| valid | 97.43% |
| test | 97.18% |

附件 3 的 30 条样本中，**没有任何一条**出现"只有语音缺失"或"只有视觉缺失"的情形。
这与题面"一个或多个模态中存在特征值全部为零的随机连续序列区间"所暗示的、按模态独立
随机删除的机制不一致。

### 2.3 token 跨度内部仍有真实的局部空洞

`|observed| / L` 的均值（附件 3）：

- 音频：0.70 ~ 0.98，均值约 0.90
- 视觉：0.70 ~ 0.98，均值约 0.88
- 训练集：音频 0.918 / 视觉 0.868（跨度内）

所以"局部连续缺失"确实存在，但它表现为**跨度内的短洞**，而不是整段音视频随机消失。
附件 4 的第 13 号样本视觉观测数为 0（音频 0.94），是唯一一个模态被整体清零的样本。

## 3. 对建模的影响

1. **训练增广必须落在观测支撑内。** 在 `[L, 50)` 上删除音视频等于让模型学习一种在
   提供数据中从不出现的输入，既浪费容量，也稀释了真实缺失条件的采样密度。v5 协议
   `span_bounded_v1` 因此只在 `observed ∩ token span` 内抽取删除区间。
2. **"缺失模态类型"的消融维度需要重新表述。** 由于语音与视觉的缺失完全同步，
   以"缺失 T / A / V / TA / TV / AV"为轴的实验在真实数据上只有 T 轴和 AV 轴可分辨。
   论文保留该网格作为压力测试，但必须说明它不是附件 3 的生成机制。
3. **不能声称还原了附件 3 的生成过程。** 观测到的特征模式与训练集同分布，说明附件 3
   大概率就是按同一流程产出的对齐特征（按样本长度截断），而非另行注入的独立随机掩码。
   这一结论与修订报告中原有的"不能称已还原生成机制"一致，现在有逐条统计支持。
4. **模型侧的正确做法**是让池化、门控与损失全部尊重观测掩码（v5 已实现），并在验证集
   上同时报告 clean、跨度内连续缺失与散布缺失三类条件。

## 4. 两个掩码必须区分开

审计过程中发现，"文本掩码"在实现里其实是两个不同的量，混用会引入一个**不会让训练
失败、只会让分数系统性偏低**的缺陷：

| 名称 | 定义 | 用途 |
|---|---|---|
| `span_obs` | 有效 token 前缀，即 `text_bert[1]` 的连续前缀 | 文本标准化；音视频观测的上界 |
| `word_span` | `1..L-2`，排除 CLS/SEP | 证据定位（特殊 token 不承载词级证据） |
| `a_obs` / `v_obs` | 非零行 | 音视频标准化与池化 |

v5 的约定是：**文本标准化与文本池化都用 `span_obs`**，两者必须一致；`word_span` 只用于
证据定位。此前若用全 50 行拟合标准化、却用 `span_obs` 施加掩码，不同长度样本会被放到
不同尺度上。修复后仓库代码路径能够逐位复现 12 次实验的验证集分数（见
`docs/实验记录_v5.md` §5）。

## 5. 附件之间的字段不一致

| 文件 | `text`(768) | `text_bert` | `audio` | `vision` |
|---|---|---|---|---|
| 附件 2 aligned_50 | 有 | 有 | 有 | 有 |
| 附件 3 对齐版本（30 条） | **无** | 有 | 有 | 有 |
| 附件 4 对齐版本（20 条） | 有 | 有 | 有 | 有 |

附件 3 不提供 768 维 `text` 字段，因此任何要在附件 3 上运行的模型都必须从 `text_bert`
token 出发。这不是实现选择，而是文件字段决定的约束；论文 §5.3 如实报告。
